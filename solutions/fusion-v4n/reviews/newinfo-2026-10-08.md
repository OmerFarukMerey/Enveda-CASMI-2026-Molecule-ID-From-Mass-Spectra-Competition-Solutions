MS1, no batch or sample id, row order is a sort by hash). Of what is there and not used, one thing carries signal: **the
set of adducts a molecule was acquired with says something about its functional groups** (within formulas, on 183 k

## 6. Decision and what was built

- **Organism prior, isotope peaks, base-peak intensity, number of spectra, row order: nothing survives.** No flag.
- **Adduct evidence on joined rows:** by the pre-stated rule a cell passes, so the flag, test, preset and notebook build
  were made as the task prescribes. **My reading is that it is not a locally supported candidate** (section 4), and it
  should not take a submission slot on this evidence alone. If the flag is ever tried, 0.25 is the pre-registered weight.
- Flag: `ADD_JOIN_MU` (default 0.0) in `fusion_core.DEFAULTS` and `nb/00_config.py`; `build_submission(...,
  add_score=callable(molecule id, list SMILES) -> values or None)`. In stage A, for a list with at least two joined rows
  and a scorer that returns values, it calls the existing `np_reorder(..., 0.0, ADD_JOIN_MU)`: joined rows are re-sorted
  among their own slots, pool rows get the popularity prior exactly as before. Off, without a scorer, with a scorer
  returning `None`, or on failure the old path runs untouched.

  Bernoulli log-likelihood of the molecule's adduct set, standardised over the list; predictions cached per structure).

  missing the run logs it, adds a `FAILS` entry (so `STRICT` stops) and equals v33b.
