## 1. What was built

**Module** `nb/embed/gen_analog.py` (pure functions; RDKit and numpy; the casmi modules and the fingerprint / key functions
are passed in). Constants fixed in `scratch/gen3/PREREG.md` before any replay: `KF 3`, `M_PARENTS 3`, `KEY_CAP 60`,
`ROW_CAP 25`, `T_ENUM 10 s`.

| step | function | what |
|---|---|---|
| logits | `spectrum_logits` | 0.5 × (mean over spectra + mean over the merged spectrum per polarity), the engine's aggregation; adduct ties broken by name, not by set order. Equal to gen2's stored logits on 56 of 60 molecules (max difference 3e-6); the other 4 are adduct ties (correlation ≥ 0.992) [M] |
| formulas | `target_formulas` | the first 3 distinct formulas of the molecule's base list (60 rows, list order) |
| parents | `PoolIndex.ranked` | for every formula `target − delta(rule)` the 3 pool rows with the highest f.z from the stored pool fingerprints; the 3 best same-formula rows for moves. Variant: joined PubChem rows as move parents (`extra_move_parents`) |
| products | `enumerate_formula` | one of the 66 rules or one of the 61 moves of gen2's table (copied; the test asserts equality with `train/gen/rules.py`), exact target formula, sanitised, one component, stereo-free |
| order | `enumerate_formula`, `interleave` | best parent rank, one step before move, number of parents, parent f.z; formulas interleaved by position × formula index |
| caps, novelty | `finish` | the first 60 products that are not pool rows get a metric key (plain InChIKey once the first 8 cost more than 40 ms each); the first 25 distinct keys that are neither a same-formula pool row nor a candidate are the rows |
| features | `finish`, `gen_features` | parent rank and f.z, number of parents and of rules that produce the row, step, rule group, own f.z and f.z / √bits, Tanimoto to the parent, formula index, order |
| policy `slots` | `place_slots` | `GEN_ANALOG_K` rows take the positions from `GEN_ANALOG_POS` of the final list; rows from there move down |
| policy `gate` | `gate_open`, `place_merge` | only below lib_max 0.7 and below `s1_max` = 2.03 of the fold-safe ranker's top score: every row gets a probability of being the answer (database rows: logistic in log rank, first row, s1; generated rows: logistic in the features above, s1, lib_max) and the list is re-sorted; database rows keep their order |
| run | `run_channel` | per molecule: exclusion keys (base list, final list), generate, place; a failure, a missing context or the 25-minute budget leaves the list as it is |

**Where it sits.** After `fusion_core.build_submission` (cell 08), not inside the engine: the rows need no ranker feature, no
forward-model score and no new dataset, the fusion cannot push them down (gen2's finding c on `genjoin`), and the placement
is exactly what was replayed. "Through the ranker" is therefore a small placement model beside the ranker, not a refit of
it: a refit needs engine features of generated rows and a new ranker dataset on Kaggle, which this task may not upload. Cell 06
stores the logits per molecule (`FS_BANK` when loaded, else the engine bank) and the fold-safe ranker's top score.

## 9. What the result can and cannot tell; not verified; mistakes

- **Local replays have had the leaderboard's sign in about half of the known contrasts** (`uregime`: 5 to 7 of 11 **[C]**).

  which is synthetic (0.63). Neither is an unidentified Enveda natural product; none exists locally (`genjoin` **[C]**).

  benchmark's, and every local database answer is a library compound, so local s1 is higher than hidden s1 for classes P and
  C: on the hidden test B's gate opens more often on database answers than here. Not quantified.

  difference of 0.47 against a threshold of 2.03 [M]; (iii) fitted at DEV's class mix (16% class N).
