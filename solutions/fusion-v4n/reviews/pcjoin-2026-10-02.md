## 0. Bottom line

1. **Injection works mechanically.** A PubChem candidate enters `Engine.candidates` exactly like a product of the
   derivative generator and receives every feature family; two methods of the engine object are wrapped, nothing in
   the public `casmi` package is edited. Cost: +0.17 / +0.5 / +0.9 s per molecule for N = 25 / 50 / 100 on one CPU
   thread. The literal notebook edit reproduces the study's lists for 96 of 96 checks (section 6).
2. **Gain side (truth only in PubChem), N = 50, per molecule with a PubChem record:** today 0.080 → 0.274 with the
   public ranker as it is (**+0.194 ± 0.018**, 153 / 27), +0.234 with the gated blend, +0.267 with the blend
   (zero-forward); on the ICEBERG prefix today 0.114 → 0.230 (**+0.116 ± 0.022**, 52 / 18), +0.145, +0.187. The truth
   is first in the final list for 16 to 22% instead of 1.5%, in the top five for 42 to 53% instead of 13%. The gain is
   present in every stratum but uneven: natural-product catalogue structures +0.107 ± 0.016 (zero-forward) and
   +0.067 ± 0.021 (ICEBERG), synthetic and other structures +0.26 to +0.54.
3. **Cost side.** After the whole fusion it is small: `c2` +0.013 ± 0.006, `c1` −0.006 ± 0.006 (public ranker, N 50).
   **That is engine-2 hiding it.** On the v1-side list alone (engine-2 fusion off in both arms) class 1 loses
   **−0.029 ± 0.010 (1 / 13)** and, with the blend, `c2` loses 0.055 against the same ranker without injection. The
   losses sit in lists with `lib_max` between 0.7 and 0.9.
4. **Best gate: inject only when `lib_max` < 0.7** (the engine's own library evidence, computable in 3 ms before the
   engine pass). It removes the class-1 cost on the v1 side (−0.002, 0 / 2) and keeps 83 to 87% of the gain: `dB`
   +0.163 ± 0.018 (116 / 11) zero-forward, +0.098 ± 0.020 (38 / 7) on the ICEBERG prefix. The list-shape detector and
   the `f.z above the best pool f.z` gates are worse on both sides. Fixed slots stay as they are for everything.
5. **Ranker.** The public ranker as it is already carries a "pool rows before PubChem rows" prior by accident (the
   tie-order code of the ranker review: injected rows are last among ties). With order-free ties an injected decoy
   tops 24 to 29% of the truth-in-pool lists. `pc_join.choose_score` therefore keeps ties order-free inside the pool
   and puts injected rows last among ties: decoy on top 5% (public ranker, order-free) and 16% (blend).
6. **Runtime on Kaggle:** about +1 s per molecule at N 50 (engine) and +0.1 s (channel); memory needs the family
   caches cleared every 50 molecules (tested). Nothing has to move in the notebook: the PubChem channel already runs
   before the v1 engine; it has to return N entries instead of 25.
7. **Recommendation: yes, one submission with it.** v4b + `PC_JOIN_N=50`, `PC_JOIN_MAX_LIB=0.7`, public ranker
   unchanged. It is the largest local effect of the day and the first one whose gain side is a mechanism the fixed
   slots cannot reach (an answer that is first in the PubChem list lands at rank 1 instead of rank 4). Conditional
   leaderboard range (section 7): **+0.002 / +0.010 / +0.03** (low / central / high); the central value assumes the
   natural-product stratum and the one public probe of the PubChem list (0.037).

## 1. Mechanism (step 1: GO)

**How a candidate enters.** `Engine.run` calls `self.generate(analogs, target, pool keys of the window)` and then
`self.candidates(target, drop_pid, generated)`. `generated` is a list of dicts (`smiles`, `key`, `formula`, `mass`,
`n_heavy`, `fp` = the 10,226 selected fingerprint bits as float32, `frags` = depth-2 fragment masses, `sim`, `steps`,
`tan`); they are appended behind the pool rows with pool id −1 and `train_sid` −1. `fe_v4/hooks_v1.install` replaces
`E.generate` by a recording copy. `prototypes/pc_join.install(E, V, order)` wraps `E.generate`, `E.candidates` and
`V.view` on the objects; `set_injection(E, records)` sets the records of the next run; with no records the engine is
untouched (N = 0 through the wrapper equals the stored rows, see "determinism" below).

**What an injected candidate gets.**

| Feature family | Generated candidate today | Injected PubChem candidate |
|---|---|---|
| library (`lib_*`) | 0 (no `train_sid`) | 0: the same, and correct (a structure outside the pool has no reference spectrum) |
| analog propagation, f.z views, element head, MetFrag-lite, subformula, context, cross | computed from `fp`, `frags`, `formula` | the same computation |
| `is_gen`, `gen_parent_sim`, `gen_steps`, `gen_parent_tan`, `gen_rank_fz` | set | **0** (not a generator product); `n_gen` counts real products only |
| `xs_*` (cross-encoder) | constant 0 for every row | constant 0 |
| fe_v4 `model_views` | from `fp` | the same |
| fe_v4 `frag2`, `fragnet`, `analog_struct` | per-structure records built from the SMILES (pid < 0 path) | the same path |
| fe_v4 `derivation` | `dg_*` columns (own parent and combo) | `dp_*` "pool candidate" columns: with order `first` the generator treats the injected keys as pool keys, so a derivative of an analog that equals a PubChem candidate is logged as a derivable pool row (`dp_hit` ...); nothing if not derivable |
| rank features with stable ties (`mass_ppm_rank`, `sf_rank`, `el_rank`, ...) | last among ties (generated rows are last) | last among ties, behind the generated rows |
| popularity in the fusion (`POP_MU`) | keeps its slot, own formula group in the forward re-rank | the same (pid < 0) |

Nothing is missing that a COCONUT-only pool row has, except the pool tables (replaced by on-the-fly records) and the
position among ties. Order `after` (generator first, an injected twin of a generated product is dropped) is 0.008 to
0.022 worse on `dB` and equal on `c2`; `first` is the default.

**Cost per candidate** (one CPU thread): standardise 0.4 ms, formula 0.1 ms, fingerprint 2.3 ms, fragments 1.7 ms =
4.5 ms; the metric key (7.7 ms) comes from the channel. The families add about as much again. Whole engine run:
3.5 s per molecule at N 0, 3.7 / 3.9 / 4.4 s at N 25 / 50 / 100 (`s6_summary.py`).

**Three things found on the way.**
- *The public engine is not deterministic across processes.* `casmi/engine.py` picks the adduct of the merged
  spectrum with `max(set(adducts), key=adducts.count)`; with tied adducts the winner depends on the process's string
  hash seed, so the merged-view FPNet item, every `fz_*` feature and the ranker score change from run to run (5 of 12
  molecules against the stored rows, score differences up to 0.3). All runs here use `PYTHONHASHSEED=0` and the
  baseline was re-run with it. The notebook has the same randomness; setting the seed there costs nothing.
- Engine features differ by up to 1e-6 between two processes (float noise) and a LightGBM split can flip on that.
- PubChem-tier SMILES are not RDKit-canonical (`CC[CH]1CN2...`); 589 of 600 change under `standardize_smiles`. The
  record carries the standardised form into the engine (as generated products do) and the base list keeps the tier
  form, so that ICEBERG scores one string per structure.

## 3. Joint ranking (step 3: GO on the gain side)

## 7. What the regime cannot tell, and a conditional leaderboard range

- **Hold-out truths are training structures with library relatives**, and "removed" means masked. Natural-product
  catalogue structures, the stratum closest to the hidden chemistry, gain a quarter to a half of what the synthetic
  ones gain (+0.07 to +0.11 against +0.26 to +0.54 with the public ranker). The stratification by analog similarity
  shows no dependence on a close analog, which argues against the threefold overstatement of generator simulations
  (pitfall 6) applying in full, but it cannot rule it out.
- **The removed truth is a well-documented PubChem compound.** Documentation does not enter the join (no popularity
  feature; `POP_MU` acts on pool rows only), and famous truths gain least here, so this bias is probably against the
  join, not for it. A typical hidden PubChem-only answer sits in a denser window of obscure isomers than a library
  compound does; the notebook's FPNet A+B lists such an answer in the 25 for 63 to 81% (pubchem review), against 59%
  for the fold-safe model here.
- **Engine-2 and ICEBERG have seen these molecules**; engine-2 is what keeps the class-1 and `c2` cost near zero after
  the fusion (section 4). GLACIER is missing. Class-1 lists here are Orbitrap / QTOF library chemistry (`lib_max` 0.97
  in the median); on timsTOF natural products it is about 0.86, i.e. more class-1 lists fall into the 0.7 to 0.9 band
  where the ungated join loses. That is the reason for the gate at 0.7 rather than 0.9.
- **The public ranker was fitted on simulations that include some of these molecules**; `ours` was not, and gains more.
- 380 molecules, 150 class-1, 169 with ICEBERG. Class-1 effects of ±0.006 are two to four molecules.

**Leaderboard scale.** Two ways, both conditional:
- *Mixtures of the mixed-regime review* (gate 0.7, N 50): public +0.038 to +0.043 zero-forward and +0.018 to +0.020
  on the ICEBERG prefix; gated blend +0.053 to +0.059 and +0.031 to +0.034. These assume that 22% of the hidden
  molecules are `dB`-like; with the list accuracy measured here that is a PubChem-list-alone score of 0.054, above
  the one public probe (0.037), so they are high by about a third before any other doubt.
- *Scaling by the probe* (the pubchem review's model): gain = X / m × g, with X = 0.037 the public score of the
  PubChem list alone (one probe on about 130 molecules, ± 0.012), m the same list's MRR on the local molecules and g
  the local gain per PubChem-record molecule (gate 0.7, public ranker, N 50):

  | Case | X | molecules, replay | m | g | change |
  |---|---|---|---|---|---|
  | low | 0.025 | natural-product catalogue, ICEBERG, a further factor 1/3 (pitfall 6) | 0.25 | 0.056 / 3 | **+0.002** |
  | central | 0.037 | natural-product catalogue, ICEBERG to zero-forward | 0.25 | 0.056 to 0.090 | **+0.008 to +0.013** |
  | high | 0.050 | all strata, zero-forward | 0.278 | 0.163 | **+0.029** |

  The natural-product g under the gate is the ungated stratum value (0.067 / 0.107) times the share of the gain the
  gate keeps (0.84); it was not measured separately. Cost side at these shares: class 1 0 to −0.002, `c2` 0 to +0.004.
  For the gated blend multiply the join part by about 1.3 and add whatever the ranker itself is worth on the
  leaderboard (unknown; +0.002 central in the ranker review).
- Today's slot merge earns about X / m × 0.08 ≈ 0.011 on this scale; the join would bring the channel to 0.02 to 0.04.
  It does not close the gap to 0.47 by itself, and it cannot reach an answer that is not in the PubChem tier.

**What failed or is weaker than it looks.** The first evaluation read the cost side as zero; the engine-2-off replay
showed the class-1 cost (−0.03) one hour later. The tie tier does nothing for our own ranker. The per-candidate
`rel` gate was rejected on the baseline numbers without an engine run. ICEBERG scores exist only for PubChem ranks 1 to
25, so N 50 / 100 on the prefix under-use the forward model; GLACIER and the GPU were not used. The `after` order was
run for N 50 on `dB` / `dA` / `c2` only. `INDEX.md` was not regenerated (no existing file may be edited): run
`python tools/gen_index.py` when the prototype, its test and this review are committed.
