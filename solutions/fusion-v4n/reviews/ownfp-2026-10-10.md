**Clean-room limit.** (1) `SPEC.md` was written by an author who had read the unlicensed package. (2) A drop-in
network must have the checkpoint's layout and the engine's input conventions; these were pinned by observing the
reference as a black box: parameter names and shapes of `fpnet_fold0.pt`, inputs and outputs of the reference
module's submodules through forward hooks, outputs of its preparation / merge / collate functions and data tables on
test inputs (`scratch/ownfp/probe_ref.py`, `probe_fit.py`, `probe_data.py`, `probe_elem.py`, `diag.py`, `diag2.py`).
Facts obtained this way: sinusoidal layout, the two intensity features, the four scalar inputs of the global token,
`ce / 10 + 1`, clamped neutral loss, pooling, the empty-spectrum convention, the tie rule at the 160-peak cut, the
merge rule (0.005 Da, sequential), the element order. (3) One traceback during probing printed two source lines of
the reference `forward`; they showed nothing the hooks had not. (4) `scratch/ranker/precompute_logits.py`, an older
script of ours that mirrors the engine's item building, was read afterwards for the refit. Decided by us without
looking: initialisation (PyTorch defaults), augmentation, how training merges are drawn, the fill of small candidate
windows, instrument rules, hold-out structures kept as negatives, training only on spectra with a cleaned peak
(1,974,410 training spectra; the reference loader reports 1,982,405). Whether this is clean enough is the host's call.

**Parity** (`scratch/ownfp/parity.py`, `parity.json`): forward pass on 512 real hold-out queries (384 single spectra,
128 merged groups) maximum |Δ logit| 0.0 on the CPU in float32, 0.10 under float16 autocast on the GPU
(logit standard deviation 1.64); peak preparation 3,000 of 3,000 spectra identical; merge 1,500 of 1,500 groups
identical; structure-to-pool map 275,810 of 275,810; element table identical except 12 charged formulas that the
reference parses wrongly; the engine's loader reads a checkpoint written by `fpnet.save_ckpt`; cache builder on row
group 0: every metadata column and offset identical for 131,072 spectra, 266 spectra with more than 512 raw peaks keep
different peaks at the cut. Hold-out table of `fpnet_fold0.pt` through our code against the stored
`base_fold0_eval.json`: same query groups, top-1 within 0.001 on all 11 subsets.

**Leak safety.** `specdata.SpecData` builds the training set from structures that are not held out, drops any
training structure that shares a metric key, a raw first block or an `inchikey14` with a held-out one, asserts that
no such identifier and no pool row is shared, and prints the line in every run (stored in the ledger and in the
checkpoint): "55,367 held-out structures ('hold', 'np'), 220,434 training structures, 1,974,410 training spectra;
identifiers shared between the two: 0; shared pool rows: 0; training structures dropped as identity twins: 0".
Hold-out structures stay in the pool as negatives, as catalogue-only rows do.

## 5. Machine: hours and incidents

- **GPU:** 11.96 wall hours of training jobs (`casmi-work\ownfp\hours.jsonl`), 8.61 hours of computation
  (`runs\ledger.jsonl`), one job at a time through `scratch/ownfp/run_queue.py` and `train/guard_run.py`, duty 0.8, at
  most 7.1 GB, no yield. A network on our own bit selection (11,598 bits, `--pool scratch/clean/pool/tables`: loader
  and leak check verified, command in section 6) was **not trained**: the budget went to the two seeds and the Enveda
  question.
- **CPU:** 38 worker-hours for the engine rows (3 to 4 workers, below-normal priority), plus about 3 for the
  LightGBM fits and 1 for the decompositions.
- **Incident 1, game detection (16:51 to 17:59 on 10-10).** `ChatGPT.exe` (the OpenAI desktop app) was not in
  `gpushare.DESKTOP`, so the trainer ran at the game duty 0.25 for 68 minutes. Fixed in `train/gpushare.py`; the
  queue was restarted at a checkpoint (step 44,000).
- **Incident 2, orphaned loader processes (15:27 on 10-10 to 04:00 on 10-11).** The trainer ended with `os._exit`,
  which on Windows leaves the DataLoader's worker processes alive. After twelve jobs 24 orphans held about 43 GB of
  committed memory; the page file grew to 51 GB and **drive C: fell to 0.3 GB free** (03:55). Consequences inside this
  work: failed checkpoint writes (`a2`, `a3`, `l24k`: re-run or resumed), engine molecules and stages with memory
  errors (re-run), no data lost. Killing the orphans returned C: to 31 GB free at once. Fixed: `train_fpnet.leave()`
  kills the process's children before exiting (verified: a 100-step run leaves no process behind). Free physical
  memory stayed above 6.8 GB whenever it was read; the commit charge was not watched, and should be.
- Disk at the end: C: about 4 GB of ours (`runs`: four checkpoints, rank files, ledger; `p4`: rows, logit cache,
  feature caches); D: +0.21 GB (the two dataset folders), 2.8 GB free.

## 6. Reproduce

```bash
export CASMI_DATA='D:\casmi-data'; P=.venv/Scripts/python; C=solutions/fusion-v4n/clean; S=scratch/ownfp
W='D:\casmi-data\directions\run\work'; O='C:\Users\hemre\casmi-work\ownfp\runs'
$P $S/parity.py                                            # parity against the reference (calls it as a black box)
$P $S/run_queue.py --budget_h 12                           # the jobs of scratch/ownfp/queue.txt (seeds, arguments), one at a time
$P $C/train_fpnet.py --work $W --out $O --tag x_ref_fold0 --eval_only 'D:\casmi-data\directions\dl\fpnet_fold0.pt'
$P $S/ablate_report.py x_ref_fold0 base_s0 base_s1         # paired tables from the rank files
$P $S/decomp.py <ckpt> <out.parquet> 4 && $P $S/decomp_report.py <out.parquet>
# P4 (CPU): rows, features, refit, benchmark
P4_NET="$O\\base_s0_final.pt" P4_NAME=base_s0 $P $S/p4_queue.py        # stages: scratch/ownfp/p4_stages.txt, workers: p4_workers.txt
$P $S/p4_bench.py feat --name base_s0 && $P $S/p4_bench.py fit --name base_s0 --out D:/casmi-data/kaggle_ds/casmi26-ours-ranker-fs3 --threads 1
$P $S/p4_bench.py cv --name ref && $P $S/p4_bench.py cv --name base_s0 && $P $S/p4_bench.py cmp --name base_s0 --half dev
$P $S/export_net.py base_s0                                # dataset folder of the network (never overwrites the checkpoint)
# not run: the network on our own bit selection
$P solutions/fusion-v4n/train/guard_run.py --free_gb 9 -- python $C/train_fpnet.py --work $W --pool scratch/clean/pool/tables --out $O --tag own11598_s0 --seed 0 --bs 256 --max_steps 82855 --resume
```
Seeds: `base_s0` 0, `base_s1` 1; ablations seed 0 except `a0_ctrl_s1`; worker generators are seeded with (seed,
worker, resume step), so a run is reproducible given its resume points up to GPU arithmetic. `base_s0` was resumed
once (step 44,000), `a3_floor` once (2,000), `l24k_s0` once (22,000).
