# Can the tail of a list lower its score? Metric source, 373,110 entries, splice test (2026-10-12)

Marks: **[S]** = stated by the metric's published source or a quoted post; **[V]** = run or computed in this study
(file named); **[I]** = inference. Nothing was submitted, posted, voted on, downloaded as a dataset, committed or
pushed; the Kaggle CLI was not used; the browser was signed out. No solution code was edited. CPU: 4 worker
processes at below-normal priority, no GPU. The visible `test.parquet` was not used.

## 0. Result

**No tail effect exists in the metric, and none of our lists contains an entry that could trigger one.** The
published code cannot lower a list's score through rows below the answer, and on 54 tables with known answers the
score is identical under every reading of the failure handling that was proposed (failing guesses skipped, keeping
their rank, zeroing the row, duplicates removed). No sanitiser was written: there is nothing for it to remove.
The v67 loss (0.398 to 0.411 against 0.443) therefore comes from answers standing at other ranks on the hidden set,
first rows included **[I]**; which molecules, is not known.

## 2. What the metric does (source)

`metric/casmi-mean-reciprocal-rank`, version 14 of 14, Apache 2.0, read in the browser on 2026-10-12 and compared by
reading with the copy pulled on 2026-10-08 (`scratch/landscape_1008/metric/code.txt`): same text. Excerpt and
points: `scratch/tailfx/metric_src.md`. All of the following is **[S]**; that the live grader runs this code is the
host's statement for v13, not something that can be checked from outside.

| Question | Answer in the source |
|---|---|
| Splitting a cell | `str(raw).split(';')`, pieces stripped, empty pieces dropped |
| Key of a guess | `MolFromSmiles` → `RemoveStereochemistry` → `TautomerEnumerator().Canonicalize` (default limits) → `MolToInchiKey(...)[:14]` |
| try / except | `except (ValueError, RuntimeError, TypeError): return None`; unparseable → `None`. Any other exception is not caught and would stop the scoring run for everybody's row, not lower one row |
| Timeout, per-row or per-molecule limit | none |
| Gate | heavy-atom element counts of the guess must equal the answer's, else `continue`. The tautomer step runs only for guesses that pass, so a slow structure of another composition is never canonicalised |
| A failing guess | a miss that keeps its position; later guesses do not move up; the row is not zeroed; the submission does not fail |
| Duplicate keys | not removed; each occupies a position. A duplicate above the answer costs one rank, a duplicate below it nothing |
| More than 25 guesses, or none | `ParticipantVisibleError` for the whole submission (no truncation) |
| The answer's key | the same function (and the same gate function); an answer without a key raises `HostVisibleError` |
| Score | first match → `1 / rank`, `break`; plain mean |

So, by the source, rows below the answer cannot change a molecule's score, and rows above it cost exactly one
rank each whatever they are. The only list property that costs anything beyond a wrong guess is a **repeated
metric key above the answer**.

## 5. What the v67 loss then is

Under the source, a score moves only when an answer stands at another rank. **[I]** The four v67 tables therefore
lose answers on the hidden set through ranks, most probably first and second rows, not through the 172 joined rows
in their tails. "Same first row on 12 of 12" is a property of the 12 visible molecules (all library hits): on the
local lists v67a and e006u share the first key on 98% (panel c1) down to 57% (mixed dB masked) of the molecules
**[V, `report.txt` section 5]**. Locally those differences favour v67a (mixed dA masked: v67a right and e006u wrong
on 65 lists, the reverse on 4), which is the opposite of the leaderboard: the local tables do not predict the
hidden set here, as `diag67-2026-10-12.md` already concluded. The size (0.032 to 0.045) is 4 to 6 answers at rank 1
on about 124 molecules, or more answers moved by a few ranks.
