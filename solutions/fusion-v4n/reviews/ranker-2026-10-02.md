MRR = MRR@25 on the metric key. "±" is one standard error; deltas are paired per molecule. Reproduce: section 8.

**How to read the numbers.** Everything below is measured on rows built from `train.parquet`, in which the true

## 0. Bottom line

1. **The v1 engine runs natively on this machine** and reproduces the Kaggle run valA: same top-1 for 250 of 250
   molecules, identical `lib_max`, top-80 Jaccard 0.997 (section 1). 4.2 s per molecule on one CPU thread.
2. **The public ranker does not recognise held-out molecules through the fingerprint bank alone. Most of it is a
   tie-order leak.** `casmi/engine.py::_rank_norm` breaks ties by candidate order = pool row order: training
   structures first (in order of first appearance in train.parquet), COCONUT-only structures after them. Inside one
   formula the mass error, the subformula score and the element-head distance are identical, so `mass_ppm_rank`,
   `sf_rank` and `el_rank` are pure row-order codes. On 3,100 fold-0 hold-out molecules with every fingerprint model
   fold-safe the ranker's in-group top-1 is 0.870 as the notebook runs it, 0.748 with order-free ties, **0.683 when the
   truth sits where a COCONUT-only row sits (where every hidden class-2 answer sits)**, and 0.469 for FPNet alone. On
   enveda-np-examples (FPNet A and B never saw them): 0.948 → 0.668 → 0.62; FPNet 0.419 (section 2).
3. **Rows**: 3,100 class-2-like, 995 class-1-like and 800 truth-dropped hold-out molecules (507,000 candidate rows,
   293 columns) and three frozen sets, all with order-free rank features (section 3).
4. **Our ranker** (section 4), whole-list MRR before the fusion, paired against the public ranker in the same situation:
   - hold-out, grouped CV: class 2 0.801 against 0.721 (+0.081 ± 0.005; natural-product catalogue structures +0.128 ±
     0.008), class 1 0.887 against 0.877 (+0.010 ± 0.006); frozen ordinary natural products (valF, 217) +0.122 ± 0.019;
   - frozen enveda-np-examples (timsTOF, famous natural products), model fitted on hold-out rows only: class 2 0.721
     against 0.729 (−0.009 ± 0.018), class 1 0.864 against 0.955 (−0.091 ± 0.016). It does not transfer;
   - packaged model (hold-out rows plus the enveda-np-examples rows), out of fold on enveda-np-examples: class 2 0.787
     (+0.058 ± 0.019), class 1 0.900 (−0.055 ± 0.015). Blended with the order-free public ranker and switched off for
     library hits (`lib_max` ≥ 0.7): class 2 +0.046 ± 0.014, class 1 −0.008 ± 0.007;
   - after the full v4b fusion, on the three Kaggle stage caches, every variant is within 0.02 of today's pipeline and
     none is distinguishable from zero (gated blend: +0.005 ± 0.006, +0.007 ± 0.010, −0.002 ± 0.002);
   - the gain on the hold-out comes from retraining on order-free, fold-safe rows, not from new features (the public
     ranker's own 160 features: 0.796). Popularity features add 0.045 on the hold-out and 0.20 on famous natural
     products: the known fame bias of the local sets.
5. **Truth removed from the pool** (drop_pid, 800 molecules; the only local rows in which the answer is not a pool
   row): the generator proposes the truth for 15.5 ± 1.3% of the molecules (20% of natural-product catalogue
   structures, 2% of synthetic ones); top 25 for 13.9%, first for 6.0%; MRR 0.083 ± 0.009 against 0.724 for the same
   molecules with the truth in the pool. 49% of the molecules get no generated candidate. The base list itself shows
   that something is wrong: a detector built on list-shape features separates truth-present from truth-absent lists
   with AUC 0.89 (section 5).
6. **Acceptance check** (now eight LB points): base lists ordered by our ranker give Spearman +0.76 to +0.88 on valA
   (cached lists +0.13) and stay negative on valF. Under every base ordering the pair v7b / v4b is wrong by +0.08 to
   +0.14 against −0.004 on the LB. Our rows remove the ranker's leak; they do not remove the blindness that produced
   the v7b miss, because the truth is still always a pool row.

Package for one submission (section 6): `RANKER` and `RANKER_LIB_GATE` flags, defaults unchanged;
`prototypes/ranker_infer.py`, model files in `D:\casmi-data\ranker_study\kaggle_dataset\casmi26-ours-ranker\`.

## 1. Phase 1: the engine runs locally (GO)

What was built. `prototypes/local_engine.py` loads the public `casmi` package and `fe_v4` families exactly as
`nb/05_v1_engine.py` does and runs a molecule like `nb/06_base_lists.py`. Differences from the notebook, all needed here:
- every fingerprint model can be swapped: the engine bank **and** the three `model_views` models `fe_A/fe_B/fe_D`
  (`V1FE` loads them itself; the notebook's `FP_BANK='fold0'` leaves them untouched, so the Kaggle run valF still had
  leaked model_views features);
- a hold-out is simulated per molecule with the engine's own interface, `E.run(..., exclude=<mask over library
  spectra>, drop_pid=...)`. The mask is built by **metric key** (`truth_mask`), so tautomer twins are purged (audit F1);
  class-1-like = only the query library is masked. No purged train.parquet has to be written;
- checkpoints are loaded with `weights_only=True`, pickles through a restricted unpickler;
- the big `.npy` tables are memory-mapped, FPNet outputs are cached per query item (`LogitCache`).

Downloaded with the Kaggle CLI (files listed first): `ahmedberatozer/casmi26-v4b-models` (whole, 1.2 GB zip),
`pool_frag_off/mass.npy` and `train_fp_sel.npy` of `casmi26-v2-pool`, the READMEs of the two public ranker-row datasets
and `prvsiyan/casmi26-ranker-features`. `pool_frag_mass.npy` arrived with 23 MB of trailing bytes (CLI resume); its
first 357,116,708 bytes have the dataset's md5 and `np.load` reads by header.

Check against Kaggle. The spectrum cache was built from `D:\casmi-data\valtest_comp\train.parquet` (the purged folder
of val1/valA) and the 250 molecules were run with FPNet A and `fe_A/B/D`, as the Kaggle run valA did
(`compare_base.py valA_purged runs/valA`):

| Compared with `runs/valA/stage_cache/base.json` (top 80) | Result |
|---|---|
| list length equal, local errors | 250 / 250, 0 |
| `lib_max` | identical for all 250 (max abs diff 0) |
| same top-1 key | 250 / 250 |
| same top-5 order / same top-25 key set / identical top-80 order | 94.4% / 91.6% / 48.4% |
| Jaccard of the top-80 keys | mean 0.997, min 0.905 |
| generated candidates in the list | same count for 99.2% (16.0 on average) |
| ranker score difference on shared keys | mean 0.012; per molecule the largest difference has median 0.017, maximum 1.14 |

The remaining differences are in the ranker score only and sit in molecules where a fingerprint logit differs: this run
is fp32 on the CPU, Kaggle is fp16 autocast on a T4 (FPNet and DreamsFP). Not proven by a GPU rerun (the GPU was
taken), but library scores, candidate sets and generated candidates, which do not depend on the networks, are identical.

Cost. One CPU thread, FPNet logits cached: 4.2 s per molecule (median 2.4 s, maximum 283 s; generation with tautomer
canonicalisation dominates the tail). Without the cache the FPNet forward pass on the CPU is 80% of the time (Kaggle
T4: 5.0 s per molecule). 3.4 GB resident per process with memory-mapped tables, growing by about 10 MB per molecule
(caches of the public code); `run_engine.py` restarts its worker child above 5.5 GB. The GPU is only needed for the
logit precompute: 3,344 molecules in 74 s with 250 MiB (`precompute_logits.py`).

Two things cost time and are worth knowing: on this shared machine torch and LightGBM are **five to twenty times slower
with 2 or more threads** than with one (FPNet forward 0.34 s against 1.7 to 2.2 s; a LightGBM fold 20 s against 558 s),
and the engine cannot run more than three or four workers in 47 GB without the memory map.

## 2. Phase 2: how much leak is left, and where it sits (GO, with a different answer than expected)

The directions review expected the ranker to fall from 0.93 to the FPNet level (0.3 to 0.4) once the fingerprint bank is
fold-safe. It does not. Truth's rank inside its same-formula group (groups of 2 or more, whole 10 ppm window):

|---|---|---|---|---|---|

| engine bank fold-safe, model_views A/B/D (= Kaggle valF) | 0.422 | 0.900 ± 0.032 | 0.800 | 0.811 | 0.667 |

| Every model fold-safe (or unseen), larger sets | n groups | FPNet alone | as run | order-free ties | truth as COCONUT-only row (3 seeds) | truth last |
|---|---|---|---|---|---|---|

Where the leak sits.
- **Fingerprint models** (expected): FPNet A alone scores 0.756 on hold-out molecules it was trained on, the fold-safe
  model 0.422. The model_views bank is a second copy of the same leak (0.900 → 0.844 when it is made fold-safe too).
- **Tie order** (new, the larger part once the models are honest). `_rank_norm` is `argsort(-x, kind='stable')`, so
  tied candidates get consecutive ranks in candidate order = pool row order. `pool_meta.parquet` is sorted by mass; rows
  of one formula have the same mass and keep the build order: training structures in `train_sid` order (96.5% of
  adjacent pairs), then COCONUT-only rows (mean relative position 0.40 against 0.57). The rule "first row of the
  truth's formula group" alone has top-1 0.379 on enveda-np-examples (random 0.045; these structures have low
  `train_sid`) and 0.228 on the hold-out (random 0.077). `sf_rank` and `el_rank` alone are exactly that rule.
  Averaging the ties of one feature at a time (enveda-np-examples, `tie_decomp.py`): `lib_max_rank` 0.948 → 0.952,
  `ap_rank + fr_rank + fz_rank` 0.952, `sf_rank` 0.943, `el_rank` 0.891, `mass_ppm_rank` 0.847, the three formula-level
  ranks together **0.677**. They are three copies of one signal, so each alone looks harmless.
- For a class-2 molecule of the hidden test this signal points the wrong way: its truth is a COCONUT-only row and sits
  behind every training structure of its formula. The column "truth placed as a COCONUT-only row" emulates that (truth
  moved directly behind a random COCONUT-only row of its group, ranks recomputed with the engine's rule,
  `prototypes/tie_order.py`). For class 1 the pool order is a *correct* prior (the truth is a training structure):
  on the class-1-like enveda-np-examples run the ranker scores 0.954 as run and 0.910 with order-free ties.
- The post-hoc recomputation is exact for six of the seven rank features (max abs diff 0) and approximate for
  `mass_ppm_rank` (the engine ranks float64 masses whose last bits differ between structures; the stored float32
  values tie). A real engine run with `_rank_norm` patched to float32 + average ties gives the same top-1 as the
  post-hoc version for 118 of 120 molecules (`check_avg_patch.py`).

What is left after both leaks are removed is evidence, not a third leak: a LightGBM ranker trained per feature block
with scaffold-grouped CV on the order-free, fold-safe hold-out rows (`phase2_blocks.py`, 2,702 groups, random 0.077):

| Block | in-group top-1 | Block | in-group top-1 |
|---|---|---|---|
| cross (library / analog × f.z) | 0.579 | frag (MetFrag-lite) | 0.318 |
| fragnet (learned fragmentation) | 0.515 | popularity (extra) | 0.246 |
| analog propagation | 0.504 | derivation | 0.151 |
| analog_struct | 0.497 | identifiers (target mass, mass ppm, fp bits, fragment count, heavy atoms) | 0.079 |
| model_views (fold-safe) | 0.468 | lib | 0.075 |
| confidence (extra) | 0.466 | descriptors, 12 incl. style-sensitive ones | 0.074 |
| fpnet (fold-safe) | 0.450 | context | 0.070 |
| frag2 | 0.447 | subformula / gen | 0.000 / 0.030 |

Blocks that could only know the truth by identifying the candidate (identifiers, context, descriptors, subformula) are
at chance. Fragnet's training roster is in its `sets.pkl` (32,000 structures): the 291 hold-out truths (9.4%) in its
fitted parts score 0.502 ± 0.030 with the fragnet score alone, the 2,402 others 0.455 ± 0.010; the untrained MetFrag
score shows the same gap on the same subsets (0.280 against 0.238), so it is the subset, not a leak. Permuting one block
inside the formula groups costs the public ranker most for `lib` (−0.27: a candidate with library spectra that do not
match is legitimately ruled out), then fragnet (−0.11), context (−0.07, the order-coded `mass_ppm_rank`) and derivation
(−0.06).

**Safe features** (used for our rows):
- all 94 engine features when (a) the fingerprint bank is a model that never saw the molecule and (b) the seven
  `*_rank` features are recomputed with order-free ties. The eight `xs_*` features are constant zero (no cross-encoder);
- `frag2`, `analog_struct`, `derivation`, `fragnet` as they are; `model_views` only with fold-safe models;
- extras computed from the above: formula-group size and share, f.z margins inside the group, library margins.

**Not safe**: `mass_ppm_rank`, `sf_rank`, `el_rank` as the engine computes them (and, to a small extent, every other
stable-tie rank); anything from FPNet A / B / D / full1 on a hold-out drawn from train; pool provenance (`src`,
`train_sid`, `np_likeness`, which is NaN for training-only rows); descriptors that depend on the tautomer style of the
SMILES (H-bond donors, carbonyl / amide / aromatic counts: training rows are InChI-derived, COCONUT rows are not).
**Not a leak but a biased prior**: popularity. It is kept out of the main model and reported separately.

One caveat stays: analog evidence is easier here than it will be for new natural products. The fold-0 split is
identity-disjoint, so a held-out library compound usually keeps close relatives in the library (analog block alone
0.50). A ranker without any fingerprint feature still reaches 0.801 on the hold-out against 0.815 with them.

## 4. Phase 4: our ranker

LightGBM lambdarank (400 rounds, 31 leaves, learning rate 0.05), one group per molecule, all candidates of the window.
Training rows: class-2 rows plus the class-1 rows (914 molecules) and the truth-dropped rows whose truth was generated
(124) of the same training folds. Folds: 5, grouped by generic Murcko scaffold (acyclic molecules by formula).
Baseline: logistic regression on 8 features. Scores compared:

- `as run`: the public ranker as the notebook computes it (pool-order ties). **Leaked on every class-2 set below and
  therefore not a fair opponent there.** For class 1 the pool order is the real one, so there it is the fair opponent.
- `class-2 order`: the public ranker with the truth placed as a COCONUT-only row. The fair opponent for class 2. It is
  still favoured in one respect: the public ranker was fitted on simulations of these very molecules.
- `order-free`: the public ranker with average ties. `FPNet`: f.z alone. `blend`: mean of the in-molecule z-scores of
  ours and `order-free`.

On molecules like its training rows (library compounds, mostly Orbitrap / QTOF spectra, one fold-safe fingerprint
model) our ranker is clearly better. On the only test-like molecules (timsTOF spectra of natural products, features
from the three public models) it is not: equal to the fair opponent for class 2 and 0.09 worse for class 1, where the
public ranker's pool-order prior and its training on these very molecules both help it.

Why it does not transfer, checked: our rows carry one fingerprint model in all three model_views slots, deployment has
three. Rerunning the frozen molecules with model A alone in the three slots (`valA_purged_A1`, `val_c1_A1`) changes
nothing: class 2 0.716 (−0.005 ± 0.018), class 1 0.864 (−0.089 ± 0.016). So the gap is the domain, not that mismatch:
the hold-out is library chemistry on Orbitrap / QTOF, class-1 rows there have library scores near 1 (median `lib_max`
0.99 against 0.86 on enveda-np-examples), and the fold-safe FPNet is weaker than A (0.31 against 0.42 in-group top-1 on
natural products).

### 4.3 The packaged model: hold-out rows plus the enveda-np-examples rows

## 6. Decision and package

**Is our ranker better where the comparison is fair?** Measured, before the fusion: on hold-out rows yes (class 2
+0.081 ± 0.005, class 1 +0.010 ± 0.006, frozen valF +0.122 ± 0.019). On enveda-np-examples the hold-out model is not
(−0.009 ± 0.018 and −0.091 ± 0.016); the packaged model, which includes those rows, is +0.058 ± 0.019 on class 2 and
−0.055 ± 0.015 on class 1 out of fold, and +0.046 ± 0.014 / −0.008 ± 0.007 as a gated blend. After the fusion nothing
is distinguishable from zero on the three stage caches. Whether any of it helps on the hidden test is not known and
these rows cannot tell: they have the truth in the pool, like the rows that mispredicted v7b.

**Which features carry it?** The same 160 features as the public ranker, retrained without the order code and with a
fingerprint model that had not seen the molecules (0.796 of the 0.801 on the hold-out). Gain shares of the packaged
model: model_views 41%, analog 20%, fragnet 11%, derivation 8%, analog_struct 7%, lib 4%, fpnet 3%, frag2 3%.
Confidence features and descriptors add 0.005; popularity adds 0.045 on the hold-out and 0.20 on famous natural
products and belongs in the fusion (`POP_MU`), where the LB can price it, not inside the ranker.

### 6.2 What the local numbers imply for the LB, and why they may not hold

The task asked for a low / central / high estimate. It can only be given conditionally: **if** the after-fusion deltas
of section 4.4 transferred to the hidden test with class shares of 16 to 33% (class 1) and 21 to 46% (class 2 with the
truth in the pool, directions 2.7), the gated blend would move the LB by 0.33 × (−0.002) + 0.21 to 0.46 × (+0.005 to
+0.007) ≈ **0.000 to +0.003**, the gated tie rule by about +0.001 to +0.006, and the ungated packaged ranker by −0.007
to −0.002. Low / central / high for the recommended submission: **−0.005 / +0.002 / +0.010**, all inside the LB's own
noise (±0.01 for a paired difference). Reasons the condition may fail: these caches have the truth in the pool; they
are 236, 217 and 250 molecules; ICEBERG / GLACIER are optimistic on them; the engine-2 gate looked ten times larger on
the same caches and came out at −0.004. The honest statement is that the package is cheap to test and that its local
case rests on the pre-fusion ranking, not on a demonstrated end-to-end gain.

## 7. What failed or is weaker than it looks

- All rows except `drop_fold0` have the truth in the pool. This is the defect that made the engine-2 gate look good
  locally; it applies to every number of section 4.
- The comparison "truth placed as a COCONUT-only row" emulates the order only. A real hidden class-2 truth also has a
  COCONUT-style SMILES; for about 10% of the structures present in both sources the styles differ enough to change the
  fingerprint (the public authors report mean Tanimoto 0.70 for those). FPNet evidence is therefore somewhat optimistic
  for every ranker here. A descriptor-only ranker is at chance (0.074), so the style is not a usable label in our rows.
- `mass_ppm_rank` is recomputed from float32 values; the engine's float64 ties differ (118 / 120 same top-1).
- The hold-out model does not transfer to enveda-np-examples; the packaged model's numbers there are out of fold over
  only 250 molecules, which are also the molecules the public models A / B were tuned to exclude and the public ranker
  was simulated on.
- Hold-out queries are mostly Orbitrap / QTOF spectra from public libraries; only enveda-180 (synthetic) is timsTOF.
  6.8% of the hold-out molecules have precursor errors above 10 ppm and can never be found.
- Analog evidence is easier on library compounds than it will be on new natural products (section 2).
- The public ranker was fitted on simulations of the hold-out and enveda-np-examples molecules. Its `class-2 order`
  score is an upper bound of what it does on unseen molecules.
- The first engine workers were lost to memory (three 6 GB processes on a machine other jobs were using) and to
  thread oversubscription; about an hour. A crash in the frozen valF evaluation (molecules without candidates at the
  end of a table) was fixed; the valF numbers come from `eval_frozen.py`. valF's twins and relabelled instruments
  (audit F1, F2) are still in the Kaggle stage cache used in 4.4 and 4.5; the twin-free labels were used.
- ICEBERG / GLACIER scores exist only in the three Kaggle stage caches; none were computed for the hold-out rows
  (out of scope here), so the after-fusion numbers rest on 236 + 217 + 250 molecules.
- `python scratch/ranker/phase5_drop.py drop_fold0 --model ...` scores the truth-dropped rows with a final model that
  was trained on them; that output is in-sample and is not used here.
- `INDEX.md` was not regenerated (no tracked file was changed; `solutions/fusion-v4n/prototypes/` is new): run
  `python tools/gen_index.py` when the prototypes are committed.
