### 2.2 The visible-id lock in V44

Facts [V]:
- The final cell holds a dict `_champion_top1` with 400 entries, `molecule_id` → SMILES, and runs
  `_wanted = _champion_top1[str(_row.molecule_id)]` for every row of the submission, then writes that SMILES first. There is
  no guard and no fallback: a `molecule_id` outside the dict raises `KeyError`.
- On the commit run (the visible 400 molecules) the log prints `V29 final top-1 locks applied: 1`: the lock changed one
  top-1.
- The structures are those of the visible `test.parquet`, which is drawn from train.

Claims [U]: forum 745715 (NicholasOOO, 10-03 23:07) says this version scored 0.417 and the previous one 0.402, concludes that
the hidden rerun reuses the visible ids and that the placeholder structure equals the hidden answer for part of them, and
asks the host to remap the ids. If the notebook version with the lock really was scored, the first half follows from the
code (otherwise `KeyError`). The second half is the poster's inference; the version history is not visible through the CLI,
and V44 also changed the ICEBERG budget and the engine-2 ranker in the same step.

For us: this is keyed to the visible test file, which `AGENTS.md` forbids, and the host has been asked to close it. Do not
adopt it. It matters only as the explanation of the 24 teams at 0.416 to 0.418, and as a reason to expect an id remap.
