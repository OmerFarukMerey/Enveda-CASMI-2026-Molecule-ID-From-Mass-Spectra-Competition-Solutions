## 2. heliosli: what the overlay does [V code, C claims]

- Cells: 45 of 47 code cells byte-identical to D0 (Data Behind v16); one metadata cell differs in a version string; one new final
  cell, "heliosli overlay v3: same-formula isomer reranker with the training-structure correction".
- The re-ranker matches the peaks of each spectrum to every candidate's one- and two-bond-cut fragments and scores them with a graph
  network plus a transformer. It re-orders the whole final list (rank 1 included) of every molecule whose library match is below
  `LIB_TAU` (default 0.9). Lists with a strong library match are untouched.
- The comment says the model scores training-set structures about 0.34 SD below the other candidates of the same list, and the deployed
  rule (`mode / alpha / delta` in `rr3_config.json`) removes that effect. A three-molecule self-test (correlation >= 0.999 with the
  offline scores) gates the overlay; any error leaves the base file unchanged.
- **Code and weights are not public.** `rr_deploy.py`, `rr_v3.py`, the encoder, the checkpoint and the config come from a dataset that
  the metadata lists as `''` (private). heliosli has no public CASMI dataset; the title offers to publish it. Until then nobody can run
  it, and without public training code it would not be eligible for prizes anyway (host ruling 750612).
- Reading [I]: about +0.005 or more over a 0.464 base, from a re-ranker that is allowed to move rank 1, while the neural fusion of the
  0.466-0.468 line loses whenever the neural model reaches rank 1. A model built for same-formula isomers with a correction for the
  training-structure bias is a different instrument from sanpier's spectrum model. Our isoxe cross-encoder is the closest thing we own;
  on s1 it touched only simulator-blind molecules (s1x 0.465, 0.000). Applying it to all non-library lists is untested.
