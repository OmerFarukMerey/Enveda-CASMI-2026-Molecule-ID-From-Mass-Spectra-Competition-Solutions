# Public data for an own NP isomer reranker, 2026-10-28

Desk research and metadata only. **No data file was downloaded.** Calls: Zenodo REST API (record metadata), GitHub API
(release and repo metadata), Hugging Face API (file lists, README), MoNA REST (`/rest/downloads/predefined`, export
metadata), HTTP HEAD on the 101 GNPS2 library MGFs (size and Last-Modified only), web pages. Local reads: the training
file (`ingest_lib`, `inchikey14`, `molecular_formula`, `instrument_type` columns), the pool table of
`casmi26-v2-pool`, the cache of the 10-09 extlib study (`D:\casmi-data\extlib\meta_keys.parquet`). The visible
`test.parquet` was not read. Scripts: the session scratchpad (`libstats.py`, `npgroups.py`, `newnp.py`, `gnpslibs.py`,
`zrec.py`), not committed. Marks: **[V]** verified at the source or computed today; **[I]** inference or estimate;
**[C]** taken from an earlier repo doc (named).

Context: s1 / sp1 at 0.472; gold needs about 0.479. heliosli's private same-formula reranker (1-2-bond-cut fragments,
graph net + transformer, training-structure bias correction) moved a 0.468-line base to 0.475
([update-2026-10-27.md](update-2026-10-27.md)). Our isoxe has isomer MRR 0.33 against the list's 0.83 on the clean NP
panel and is positive only on enveda-180 ([fz-2026-10-27.md](../../solutions/fusion-v4n/reviews/fz-2026-10-27.md),
[isoxe-2026-10-18.md](../../solutions/fusion-v4n/reviews/isoxe-2026-10-18.md)).

## 0. Bottom line

1. **There is no large public pool of labelled NP spectra that train lacks.** Every big NP library (GNPS NP
   collections, MSnLib NIH-NPAC and TargetMol NP, BMDMS-NP, Vaniya/Fiehn NPL, ReSpect, RIKEN PlaSMA, MassBank, MoNA) is
   in train, directly or through the MS-DIAL kit (the `riken` source). The study of 10-09 found 1,068 structures beyond
   train in GNPS2 + MassBank 2026.03 + MultiMS2, **189 of them natural products** [C extlib]. Nothing published since
   changes this [V, section 2].
2. **More data is not the lever. How train's NP data is used is.** isoxe trained on 39,526 groups, half of them
   enveda-180 (weight 2), with PubChem-window negatives. Train holds about **25,000 COCONUT structures outside
   enveda-180, 16,489 of them in 4,233 same-formula NP groups**, with a median of **20 COCONUT isomers per structure**
   [V]. An NP-only, list-aware training set from train alone is the first thing to try. It needs no download. This
   matches the team rule "model over data".
3. **The honest held-out NP set is already on disk.** The 189 NP structures (2,228 spectra, 181 in the test mass
   range) from MassBank 2026.03 (EAWAG 86, MLU 33), MultiMS2 (42) and GNPS (about 28) are absent from train.parquet
   and so absent from every public FPNet and ranker. By date, most also post-date MassSpecGym (2024) and the
   MS2DeepScore 2.0 training run (2025-08) [I]. The MassSpecGym key check needs one small download (section 5).
4. **NIST traps found today:** TIMS-Bench (Enveda, 9.1 GB zip) ships a reference library built with NIST23 HRAM. The
   IPB "Open Mass Spectrometry reference library" and the MS-DIAL kit include the Bruker MetaboBASE vendor records.
   MoNA exports include "NIST Glycan Reference Library", "Plant Metabolites NIST" and "MetaboBASE". **Do not download
   the first two. Filter the third if it is ever downloaded.**

**Hard negatives for an NP isomer model:** the right negative is a **COCONUT same-formula isomer**, ideally one that
the deployed pipeline actually lists (pool + PubChem-window rows the s1 / sp1 lists contain). isoxe used ≤8 PubChem
window rows "most similar first" plus pool isomers. On NP molecules the PubChem window is dominated by synthetic
structures that a real NP list never shows, so the model learns the wrong contrast [I; consistent with isomer MRR 0.33
against the list's 0.83].

## 4. Recommended training-data plan (ranked by expected value)

The evidence for every step is thin: the only positive external signal is heliosli's +0.005 to +0.007 from a private
model with unknown training data. Each step needs a pre-registered gate on the clean instrument, as FZ had.

| Rank | Step | Data | Download | Cost on the shared RTX 4070 Ti SUPER [I] | Why |
|---|---|---|---|---|---|
| 1 | **NP-only, list-aware groups from train.** Positives: the 25,090 COCONUT train structures outside enveda-180 (4,233 multi-structure formulas). Negatives: COCONUT isomers of the same formula (median 20), sampled the way the pipeline lists them, plus other train structures of the formula. Inputs include the base list rank or score, so the model learns a residual over the list (heliosli's `1/(3+b) + a/(3+x)` form). Add heliosli's training-structure correction: either a learned offset for "candidate ∈ train" or negatives drawn half from train structures | train.parquet, pool | none | featurise ≈0.4 M candidates × 12 ms ≈ 1.5 CPU-h (3 workers below normal); train 2 seeds ≈ 1-2 GPU-h (isoxe took 35 busy min for 40k groups) | addresses the measured failure modes: enveda-180 dominance, PubChem-style negatives, no list information, training-structure bias |
| 2 | **Honest NP held-out set** = the 189 NP structures beyond train (2,228 spectra; EAWAG 86, NEXUS 42, MLU 33; Exploris / QE / ZenoTOF) minus MassSpecGym keys, with candidate lists built by the pipeline's own channels. Second instrument: the clean panel (enveda-np-examples) after purging MassSpecGym keys, for timsTOF realism | extlib cache on disk; MSG key list | MSG tsv 261 MB | minutes | not in train, so not in any FPNet or ranker; mostly post-date MSG and MS2DeepScore. **But** 189 molecules give MRR noise of about ±0.03 and none is timsTOF, so it is a harm gate, not a tuner |
| 3 | **DreaMS SSL backbone** as the spectrum encoder (fine-tuned jointly with the fragment-annotation head) instead of a from-scratch 3-layer encoder | weights on disk | none | 116 M params: 6-10 GPU-h per seed, or 1-2 days of wall time at game duty 0.25 | the only NP-rich prior that is allowed and free; isoxe "blind" scored 0.116, so the spectrum side carries little today |
| 4 | **Cross-instrument augmentation**: MultiMS2 ZenoTOF CID 20/40/60 eV spectra of train structures (18,152 spectra, already on disk), mixed into the groups as extra spectra per structure | on disk | none | negligible | QTOF-type CID is closer to timsTOF than Orbitrap HCD. Weak, cheap |
| 5 | MSnLib v8 MSn trees for NIHNP and TargetMol NP as an auxiliary task (predict which fragments are genuine 1-2-cut pieces) | Zenodo 21105617 | 558 MB (4 MGF) | parsing hours; small training add-on | richer fragment supervision for NPs. Unproven, so last |
| 6 | Distillation from GLACIER / ICEBERG / CFM-ID (ISDB) on COCONUT isomer groups that train lacks | ISDB 1.66 GB, or local forward runs | 1.66 GB | ISDB lookup cheap; local GLACIER runs days | more NP groups, but the model learns the teachers' order, and the list already contains GLACIER. Expected value low |

Not recommended: Enveda-180 full (drug-like), TIMS-Bench (NIST23 inside, 45 NPs), IPB aggregate (no licence, NIST /
vendor content), GNPS propagated libraries (inferred labels), WUR (gated), CASMI 2022 in the pipeline (no licence).

**How to keep the evaluation honest.** Remove from every evaluation set the keys of (a) train.parquet when judging
anything trained on it, (b) MassSpecGym (ICEBERG, GLACIER, MIST), and (c) the MS2DeepScore training libraries (GNPS,
MassBank, MoNA, MSnLib before 2025-08) if MS2DeepScore enters. Group the split by Murcko scaffold, as isoxe did.
Freeze the gate before training. Tune nothing on the 189.

**Disk.** D: 61 GB free, C: 24 GB free today [V]. Steps 1-4 need no new space beyond feature caches (≈5-10 GB).

## 6. Not verified

- That train's `riken` is the MS-DIAL VS19 kit and `pluskal_ms2` is MSnLib v8: inferred from counts, not from keys.
- That `all_sorted_library_spectra.parquet` in TIMS-Bench contains NIST23 spectra: inferred from the paper's methods;
  the file was not opened, and should not be.
- MassSpecGym's composition and size: from the paper as remembered, not re-read today; the MSG key overlap with the
  189 held-out structures is unknown until download 1.
- Which MoNA sub-libraries train's `mona` holds; the instrument behind its 6,022 Bruker Maxis spectra.
- BMDMS-NP licence: the GitHub repository (chalbori/bmdms-np) is AGPL-3.0 for code; the spectra's terms were not found.
- The licence of CASMI 2022 data; LEAFBot's instrument.
