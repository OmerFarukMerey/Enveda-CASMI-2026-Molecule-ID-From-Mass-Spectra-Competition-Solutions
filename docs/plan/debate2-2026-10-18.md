# Debate 2: agreed plan (Claude + Fable 5.1 + Codex, 2026-10-18)

Inputs: brief.md, codex_r1.md, fable_r1.md, round2.md, codex_r2.md, fable_r2.md.

## What the three agree on
- The local "stack1-like" replay is a surrogate (fold-safe FPNet, rescaled gates), not stack1's real engine 1
  (`fpnet_full1` + `ranker_v4b`, leaked on every local molecule). Changes to networks or the base list cannot be
  validated locally (explains v67 −0.032, comply-s2 −0.048 vs ~0 locally).
- Every local study of 10-17/18 optimised order among database rows; 30-50% of hidden answers are in no database.
- Verified in code: stack1's fusion gives rows engine 2 does not list no vote and drops engine-1 scores and the
  generated flag (cell22 l.260, cell30 l.517-531); ICEBERG is used only when GLACIER is absent, for the PubChem list
  order and the frag-gap gate (cell26/30/34); glacierft froze the fragment generator, so it does not bound a structural
  fine-tune.
- Retracted: "rel grows with set bits/mass" (Spearman −0.03 on 257 panel molecules); 2-member formula groups are
  immaterial (median window group size 39).
- GPU model projects (pairwise isomer specialist, structural GLACIER fine-tune, negative-mode scorer) are deferred until
  the generated-candidate question is answered.

## Disagreements and resolution
- Fable's four source-attribution probes measure each source's contribution to the public MRR, not the class mix
  (Codex). Kept as optional; Codex's design answers the decision question directly with fewer submissions.
- Fable B1 (impute an engine-2 vote) needs full engine-2 membership, not top-40 absence (Codex): deferred.
- Fable B3 (engine-1 margin shield): saved scores are popularity-adjusted; deferred.

## Plan
1. CPU, now (no submission): patch stack1's notebook to capture raw ranker scores, generated flags, parent similarity
   and full engine-2 membership before truncation. Freeze ONE generated candidate per molecule by a fixed rule:
   highest raw-ranked generated candidate within engine 1's top 3, `lib_max < 0.5`, parent similarity >= 0.6, currently
   below rank 3 or absent. Build three switch variants (G-current, G-first, G-floor3); switch off must be byte-identical
   to stack1. Private commit runs only. Gate: any failed equivalence or provenance check blocks the probes.
2. LB probes, 2 submissions, user approval required:
   - G-current: only the frozen candidates at their current final rank, placeholders elsewhere. Measures the credit
     stack1 already gets from them.
   - G-first: the frozen candidates alone at rank 1. Measures their top-1 precision independent of fusion.
   Gross rank-3 benefit = G-first/3 − G-current. Continue only if >= 0.004.
3. LB, 1 submission, user approval required: G-floor3 = stack1 with exactly those candidates moved to rank 3
   (ranks 1-2 kept). Keep only for a net gain >= 0.004 vs 0.451; a tie or loss closes the branch, no threshold search.
4. Only after 2-3: decide on GPU work (Codex's projects) or Fable's B1/B3.
